# ADR-0029：Structured Financial Analysis（阶段 4B.2C.2）

- 状态：已接受
- 日期：2026-08-09
- 决策人：InsightForge 项目

## 决策

1. **4B.2C.2 状态：implementation completed / automated tests completed / live acceptance not required（不开放 Financial Analysis HTTP 端点）**。4B.2C.2 把 4B.2C.1 的 provenance 基础接上 LLM：**Financial Calculation[] + research question → DeepSeek 结构化分析 → FinancialClaimCandidate[] → 确定性 alias/ref resolution → FinancialClaimDraft(v3) → `FinancialClaimService.create_claim_batch` 原子持久化**。它是 4B.2C Financial Analyst 的**第二环（LLM 解释数值）**，也是 4B.2 的收尾。**0 Chroma query / 0 Retrieval / 0 LangGraph analysis node / 0 Report / 0 Audit / 0 tools / 0 web search**；真实 LLM 只用于**一次受控 smoke**（不走自动化测试）。

2. **包位置 `app/analysis/financial/`（E）**：`contracts.py` / `errors.py` / `packs.py`（Calculation/Evidence Pack + C/E ref resolution + numeric guard）/ `prompt.py`（system/data 分离 + 定界）/ `adapters.py`（DeepSeek 生产适配器）/ `factory.py`（Settings → model）/ `service.py`（10 步流程）。镜像 4B.1 的 `app/analysis/claims/` 结构，但针对 Financial 域。

3. **冻结身份（I）**：`FINANCIAL_ANALYST_NAME = "structured_financial_analyst"`、`FINANCIAL_ANALYST_VERSION = 1`、`analysis_domain = financial`；persisted `analyst_name` / `analyst_version` / `analyst_model_id`（=`provider:model` = `deepseek:deepseek-v4-flash`）一并落库可追溯。

4. **请求 / 决策契约（D）**：`FinancialAnalysisRequest`（company_id UUID / research_question trim 非空 / calculation_ids 1..20 去重 + canonical 排序 / additional_evidence_ids 0..20 去重 + canonical 排序）。`FinancialClaimCandidate`（claim_kind **只允许 inference / risk**——**schema 层拒绝 fact 与 relative_valuation**：定量事实已由确定性 `FinancialCalculation` 承担，Analyst 只解释并判断风险、不重复 fact Claim；更低层 domain 契约 `FinancialClaimDraft` 仍支持 fact，但 service 层 `_check_kind_policy` 对 Financial Analysis 路径兜底，即使绕过 Pydantic 也会 → `FinancialAnalysisClaimKindPolicy`，每条 **≥1 support_calculation_ref**，Calculation ref 格式 `C<number>`、Evidence ref 格式 `E<number>`——格式不同，C 编号混进 Evidence list / E 编号混进 Calculation list 即 schema 拒绝；**无 reasoning / chain-of-thought / analysis_domain / company_id / formula / result_value rewrite / fingerprint / provenance IDs / Report text**）。`FinancialAnalysisDecision`（relevant=false → 空 claims + 可选 reason_code；relevant=true → 1..3 claims + reason_code=None；无完全重复 Claim）。`FinancialAnalysisReason` 只允许 not_relevant / insufficient_calculations / insufficient_evidence（无 prediction / recommendation / buy / sell）。

5. **LLM 前验证（F）**：Service 先对每个 Calculation 执行 `FinancialCalculationService.verify_calculation_integrity`（缺失 → `FinancialAnalysisCalculationNotFound`、company != request → `FinancialAnalysisCalculationCompanyMismatch`、重放损坏 → `FinancialAnalysisCalculationCorrupted`），再加载 inputs → Observations（缺失 / 跨公司 → Corrupted）与 additional Evidence（缺失 / 跨公司 → `FinancialAnalysisEvidenceCompanyMismatch`）；**全部校验通过后关闭 DB session**——LLM 调用期间不持有 DB transaction / connection。

6. **Calculation/Evidence Pack 最小投影（G-H）**：`build_calculation_pack` 按 `str(calculation_id)` 升序编号 **C1..Cn**（确定性，与提交顺序无关），只含必要字段（calculation_ref / calculation_code / result_value 按存储表达 / result_unit / formula_version / period_summary 确定性 / statement_scope 从 inputs 派生 / deterministic_display_value 程序生成 / inputs 摘要 role+metric_code+period+normalized_value_cny+unit=CNY）；**不发送** calculation UUID / observation UUID / fingerprint / Evidence UUID / DB IDs / RawArtifact / locator / Chroma。`build_evidence_pack_allowing_empty` 复用 4B.1 EvidencePack（E1..En 按 `str(evidence_card_id)` 升序），additional evidence 允许 0 条。

7. **Numeric-literal guard（J，Final Closeout 扩展）**：`assert_statement_has_no_numeric_literals`——statement 禁止 ASCII digits / full-width digits `０-９` / `%％` / 中文数字字符（`零〇二两三四五六七八九十百千万亿兆`）/ 定量短语（`百分之 / 倍 / 翻倍 / 翻番 / 过半 / 半数 / 一成 / 一半 / 一点`）；任一 claim 违反 → `FinancialAnalysisNumericLiteralForbidden`，**整次分析失败 0 写**；**不自动删数字、不自动改写、不让第二个 LLM 修正**。**设计裁决**：`一` 与 `点` 本身**允许**（spec D 明确允许"该指标反映公司存在一定盈利空间"——"一定/进一步/观点"等常用非数量词必须可用），真正的量与数字由字符 / 定量短语零暴露（required reject 用例全部命中：`20%` / `２０％` / `两成` / `百分之二十` / `一倍`（倍）/ `翻倍` / `二〇二五`；`一成`/`一半`/`一点` 以短语捕获）。展示值（ratio 0.2 → "20.00%" 用 `ROUND_HALF_EVEN` quantize，cny → "X CNY"）由程序生成，模型不得改写。

8. **Ref resolution（L）**：`resolve_decision_refs`——C → calculation_id、E → evidence_card_id，**不 fuzzy resolve、不自动猜 UUID**；未知 C/E → `FinancialAnalysisUnknownRef`；同一 ref 跨 support/contradict/context 两个 relation → `FinancialAnalysisRelationConflict`；组内去重 + canonical 排序；**全部 candidate 先完成 resolution，任一失败 → 整次 0 写**。

9. **Service 10 步流程（O）**：①防御性 request 校验 → ②短 DB session 加载并校验全部 Calculation + additional Evidence → ③关闭 DB session → ④构造 C/E alias → ⑤调 `FinancialAnalysisModel.analyze`（provider 失败 → `FinancialAnalysisModelUnavailable`、输出无法解析 → `FinancialAnalysisMalformedOutput`）→ ⑥防御性 double-check schema → ⑦numeric-literal guard → ⑧ref resolution → ⑨构造全部 v3 FinancialClaimDraft（analyst 身份固定 + `_check_kind_policy` 兜底）→ ⑩`FinancialClaimService.create_claim_batch`。**不创建 Report / DraftSection / ReviewIssue**；不接 LangGraph 分析节点；不调用 Retrieval / Chroma / RawArtifact / tools / web search；**Financial Analyst 不计算任何财务指标、不修改公式结果、不做宏观因果 / 估值**。

10. **原子批量持久化（N）**：`FinancialClaimService.create_claim_batch(drafts)`（1..3 个）——**all-drafts-validate-first**（开事务前全量加载 + policy 校验 + fingerprint 派生，任一失败 → 整批 0 写）+ **单 transaction + ordered result**（`FinancialClaimBatchItem(ordinal, claim_id, replayed)`；`FinancialClaimBatchResult.items[i]` 永远对应 `drafts[i]`）；`FinancialClaimIntegrityError → 显式 rollback + raise`、`SQLAlchemyError → 整条 rollback + PersistenceFailed`；**无 compensating delete**。

11. **LLM 抽象 + 生产适配器（P）**：`FinancialAnalysisModel` Protocol（`model_id` + async `analyze(context, calculation_pack, evidence_pack) → FinancialAnalysisDecision`）；`FakeFinancialAnalysisModel` 用于自动化测试（**0 真实 LLM**）；`DeepSeekFinancialAnalysisModel` = 懒加载 `ChatDeepSeek` + `with_structured_output(FinancialAnalysisDecision)`，`temperature=0.0`、**显式关闭 thinking**（`extra_body={"thinking": {"type": "disabled"}}`——DeepSeek V4 Flash 默认 thinking，temperature=0 不等于关闭；结构化分析需要稳定受约束输出且不产生 `reasoning_content`）、只启用 structured-output、**不绑定 tools / web search**；`model_id = f"{provider}:{model}"`（无 immutable revision，不伪造 @rev）；`OutputParserException → FinancialAnalysisMalformedOutput`、其余异常 → `FinancialAnalysisModelUnavailable`。**不泄露** raw provider response / API key / 完整 prompt / reasoning_content。

12. **Gate 0（A-C）——Financial Claim source Evidence 语义（随 4B.2C.2 交付）**：
    - **A（Calculation 承担 relation 语义）**：v3 下 Calculation 承担 supports / contradicts / context 语义；**automatic source Evidence expansion → ClaimEvidenceLinks 一律 relation=context**（source Evidence 只提供 provenance context，不重复表达 relation）；`additional_*_evidence_ids` 保持调用方指定 relation。**Calculation 本身绝不提升 authority**。
    - **B（schema v3，无新 migration）**：`FINANCIAL_CLAIM_SCHEMA_VERSION = 3`、`FINANCIAL_CLAIM_SCHEMA_VERSION_V2 = 2`；`FinancialClaimDraft` 携带 `claim_schema_version`（默认 3），新创建 Financial Claim 全部 v3；**v2 保持 legacy replay semantics**（旧 v2 Claims 继续用 v2 fingerprint / 旧 propagation 正常 replay，不回头改 v2）。v3 fingerprint 内容 = v2 内容 + 标识（source Evidence 全部按 context 展开后的最终链路）。**无需新 DB migration**（Alembic 保持 0022 head）；v2 / v3 因 fingerprint 含 `claim_schema_version` **不错误 collision**。
    - **C（v3 critical source policy）**：v3 下 critical Claim 需任一 support Calculation 的 source Evidence 中 `critical_claim_eligible_snapshot=true`，**或** `additional_support_evidence_ids` 中存在 eligible Evidence；否则 `FinancialClaimCriticalEvidenceInsufficient`。**Calculation 本身绝不提升 authority**。

13. **错误分类（`app/analysis/financial/errors.py`，11 个 + 稳定 code）**：`FinancialAnalysisError` 基类 + InputError / CalculationNotFound / CalculationCompanyMismatch / CalculationCorrupted / EvidenceCompanyMismatch / MalformedOutput / NumericLiteralForbidden / UnknownRef / RelationConflict / ClaimKindPolicy / ModelUnavailable；错误消息不泄露 calculation / evidence 正文、prompt、API key、DB URL、raw provider response。

14. **测试（Q，Final Closeout 扩充）**：**73 项单元**（`tests/analysis/financial/`：test_contracts 冻结常量 / request normalization / candidate schema / decision rules + **fact→reject、inference/risk→accept**；test_packs C1..Cn 确定性 / display value / period summary / 最小投影 / **numeric guard（ASCII / full-width / 中文数字 / 百分之 / 成 / 倍 / 翻倍翻番 / 过半半数 / 一·点非数量词 accept / numeric-context 季月年期日号 reject）** / ref resolution；test_prompt system-data 分离 / 定界 / injection 即 data / 最小投影，零 DB + `FakeFinancialAnalysisModel`）+ **20 项集成**（`tests/integration/test_financial_analysis_service.py`，真实 PG + 真实服务链 seed company/evidence/observation/calculation + fake model：v3 claim 落库（analyst 身份 / analysis_domain / model_id / v3 claim_schema_version / calculation links / source 自动 context + additional context）、relevant=false 0-claims、Calculation 缺失 / 跨公司 / 重放损坏 / additional Evidence 缺失 → 稳定错误且**不调用 LLM**、numeric-literal guard / unknown C ref / cross-relation conflict → 0 写、**fact candidate → MalformedOutput 0 写、中文数字 statement → NumericLiteralForbidden 0 写、`_check_kind_policy` 拒绝 fact draft → ClaimKindPolicy、合法 inference/risk → 落库、smoke `_cleanup` 0 残留**、malformed output → MalformedOutput、model unavailable 透传、critical 缺 eligible → `FinancialClaimCriticalEvidenceInsufficient`（0 写）、replay 同决策再分析 → replayed_count=1 同 claim_id、多 claims ordered result、模型收到最小 pack（无 UUID / fingerprint / observation UUID））。全量 **1505 非集成 + 438 集成通过**（4B.2 = FINAL 后的最终全量回归，见 ADR-0030）。全程 0 真实 LLM / 0 Chroma / 0 LangGraph / 0 Report 表。

15. **真实 DeepSeek 受控 smoke（R，validation 阶段）**：受控 real DeepSeek smoke 走**生产适配器**（`DeepSeekFinancialAnalysisModel`，不得直接调用 SDK）；seed 真实 HTML 链 → Observation → Calculation（C1 yoy_growth_rate 0.2 → "20.00%"、C2 operating_margin 0.15 → "15.00%"）→ `FinancialAnalysisService.analyze` → 校验 schema / numeric guard / ref resolution → 打印摘要（provider / model / latency_ms / claim_count / claim_kinds / numeric_guard_success / ref_resolution_success / cleanup_success）→ **清理全部 seed 数据并实际查询 0 残留**。**不记录** API key / 完整 prompt / reasoning_content / raw provider response。**开发发现（第一次 smoke，非 accepted output）**：模型输出了 2 条 fact/high Claim，其中「公司经营利润率处于健康水平，主营业务具备较强的盈利能力。」使用评价性结论词且为 fact——暴露 claim-kind 与评价词边界问题 → 收紧为 **Analyst 只输出 inference / risk**、prompt 禁止无基准的评价词。**修正后 smoke（2026-08-09，Final Closeout accepted output，单次受控调用）**：provider=deepseek、model=`deepseek:deepseek-v4-flash`、latency_ms=10664、relevant=true、claim_count=2（created=2 / replayed=0）、reason_code=None、claim_kinds=`['inference','inference']`、numeric_guard_success=true、ref_resolution_success=true、cleanup_success=true；2 条 Claim statement 全部纯定性无任何数字形式且 refs 全部落在 C1/C2（inference/high「公司营业收入保持增长态势，经营规模持续扩张。」、inference/medium「公司经营利润率反映出主营业务具备一定的盈利空间，但需结合行业与历史水平进一步判断其相对表现。」）；运行后清理确认 **0 残留**。

16. **文档边界（S）**：stage-4-plan.md / README 统一为 **4B.2A completed**、**4B.2B completed**、**4B.2C.1 completed**、**4B.2C.2 completed**、**4C.1 next = Macro Context Analyst**、**4C.2 later = Valuation**、**4D later = Claim Synthesis / Conflict / Evidence Gap**、Stage 5 = Report + Audit（不提前标记）。Alembic head = 0022。

## 后果

- **4B.2 完整收尾**：从已登记 Observation → 确定性 Calculation → Financial Claim provenance → LLM 解释 → v3 Claim，形成 **Claim → ClaimFinancialCalculationLink → FinancialCalculation → FinancialMetricObservation → EvidenceCard → Source** 可重算证据链 + **analyst_model_id 可追溯**。
- **角色边界严格**：Analyst 只做判断（相关性 / statement / kind / confidence / importance / C·E 编号引用），**确定性全交给代码**（C/E alias、ref resolution、numeric guard、v3 fingerprint、create_claim_batch 原子持久化）；**Analyst 只输出 inference / risk，不输出 fact Claim**——定量事实已由确定性 `FinancialCalculation` 承担，Analyst 不重复事实；Analyst 不计算、不改写数值、不做宏观因果 / 估值、不生成 Report；LLM claim statement 必须纯定性（中文数字表达由 deterministic guard 禁止）。
- **v2/v3 双轨安全**：已有 v2 Claims 继续 legacy replay；新 Claims 全 v3；fingerprint 含 schema_version，无 collision；无新 migration。
- **0 partial writes / 无 compensating delete**：任一 candidate 校验失败 → 整次 0 写；全部 drafts 先 validate 再单 transaction 持久化。
- **模型最小暴露**：模型只收到 C1..Cn / E1..En 必要字段与程序生成的展示值，不接触 UUID / fingerprint / locator / raw / Chroma；prompt 注入在应用层边界内被当作 data。

## 明确不做（边界）

不实现 Macro Analyst / Valuation Analyst（4C）；不实现 Claim Synthesis / Claim Conflict / Evidence Gap（4D）；不接 LangGraph workflow integration；不生成 Report / DraftSection / ReviewIssue / Audit（Stage 5）；不开放 HTTP API；不实现自动交易 / 技术分析 / 短期预测 / 买卖建议；**不开始 4C**。
